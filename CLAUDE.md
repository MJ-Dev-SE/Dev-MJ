# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

This is a Create React App (react-scripts) project. Run from the repo root:

- `npm start` — dev server with hot reload at http://localhost:3000
- `npm run build` — production build to `build/`
- `npm test` — Jest + React Testing Library in watch mode
- `npm test -- --watchAll=false` — run tests once (CI style)
- `npm test -- src/App.test.tsx` — run a single test file
- `npm test -- -t "renders learn react link"` — run tests matching a name

There is no separate lint script; ESLint runs through `react-scripts` (config in `package.json` under `eslintConfig`, extending `react-app`).

## Architecture

Single-page-scroll React 19 + TypeScript portfolio site, styled entirely with Tailwind CSS. No backend — the contact form posts directly to FormSubmit (`https://formsubmit.co/...`), and certificate PDFs are served as static assets.

**Routing & layout shell.** [src/App.tsx](src/App.tsx) is the layout root: it wraps everything in `BrowserRouter`, gates the app behind a branded `LoadingScreen` (shown once per load, then a center-expand entrance animation plays via the `pageEntrance` variant in [src/components/motion.ts](src/components/motion.ts)), and renders a persistent shell — `Navbar` (sticky top header) and `Footer` around a `<main>` holding the `Routes`. There is effectively **one route**, `/` (`Home`, the single scrolling page); `BrowserRouter`/`AnimatePresence`/`pageTransition` are kept for structure and future routes, but everything the user sees lives on `/`. Certifications is a section on that page, not a separate route.

**Pages vs components.** `src/pages/*` are route targets; `src/components/*` are reusable pieces. `Home` is a thin composition root that stacks section components in order: `HomeIntro`, `AboutSection`, `SkillsSection`, `ExperienceSection`, `ProjectsSection`, `CertificationsSection`, `ContactSection` — each wrapped in [`<ScrollReveal>`](src/components/ScrollReveal.tsx). Each section is a `<section id="...">` (`home`/`about`/`skills`/`experience`/`projects`/`certifications`/`contact`) with `scroll-mt-24` so the sticky header doesn't cover it when scrolled to.

**Scroll reveal is a "reverse spiral."** `ScrollReveal` wraps every section in a framer-motion `whileInView` that unwinds it into place (rotate `-45°`→0 + scale `0.75`→1 + fade) via the `spiralReveal`/`spiralViewport` in [motion.ts](src/components/motion.ts). `spiralViewport` is `{ once: false }`, so it replays every time a section re-enters view (both scroll directions). The rotation can push content past the viewport edge, so the app shell in `App.tsx` carries `overflow-x-clip` (`clip`, not `hidden`, so the sticky navbar still works) to kill the horizontal scrollbar. Respects `prefers-reduced-motion` (renders children plainly).

**Navigation is anchor-based, not route-based.** [src/components/Navbar.tsx](src/components/Navbar.tsx) renders plain `href="/#<id>"` links (relying on `html { scroll-behavior: smooth }` in [src/index.css](src/index.css)) and self-manages an `IntersectionObserver` over all seven section ids to highlight the active link (scrollspy). Top-level items are Home / About / Skills / **Experience** / Contact; **Experience is a hover dropdown** whose children are **Projects** and **Certifications** (those two are not top-level items). The parent highlights when any of experience/projects/certifications is the active section. There is no sidebar; mobile gets a dropdown panel under the header with the Experience children indented. The active-link indicator uses **dark text on a light `clay-200` pill** (never white text — see the readability rule under Styling).

**Content lives inline in components, not in data files.** Tech-stack groups, experience entries, project cards, and certification lists are hardcoded arrays inside the components that render them:
- `SkillsSection` owns `techStackGroups` (rendered as clickable category pills + an item grid).
- `ExperienceSection` owns a resume-style `experience` array (role/timeline entries with a "see more" modal) — this is distinct from `ProjectsSection`, which owns the portfolio-piece project entries. These used to be near-duplicates of each other (one set living inside the old carousel `Hero.tsx`, one inside `pages/Projects.tsx`); they're now split by purpose instead of duplicated.
- Certifications are two arrays (`fundamentalCertifications`, `aiCertifications`) at the top of [src/components/CertificationsSection.tsx](src/components/CertificationsSection.tsx), tab-switched in the UI, with a hover-to-preview PDF modal. Each entry points to a PDF in `public/certifications/` (via `filePath`) or an external `link`.

**ProjectsSection is an auto-rotating 3D carousel.** [src/components/ProjectsSection.tsx](src/components/ProjectsSection.tsx) arranges the project cards on the surface of a 3D cylinder (`perspective` + per-card `rotateY(i*STEP) translateZ(RADIUS)`). The whole cylinder's `rotateY` is a framer-motion `useMotionValue` spun by a `requestAnimationFrame` loop: it **auto-rotates** (`SPIN_SPEED` deg/s) starting `START_DELAY` ms after the section scrolls into view (`useInView`), **pauses on hover (desktop) or press-and-hold (mobile touch)** and resumes on release, and is independent of scroll (scrolling the page never stops it). Tune via the `PERSPECTIVE`/`RADIUS`/`SPIN_SPEED`/`START_DELAY` consts. Under `prefers-reduced-motion` it falls back to a plain readable grid of `<ProjectCard>` (the only place `ProjectCard` is still used). No GSAP/ScrollTrigger — framer-motion only.

**ProfileCard is a 3D flip card.** [src/components/ProfileCard.tsx](src/components/ProfileCard.tsx) front is the **cinematic glitch portrait** — [`<GlitchPortrait>`](src/components/GlitchPortrait.tsx) renders `/portrait.jpg` full-bleed with horizontal slice displacement + cyan/orange chromatic aberration + scan lines + digital static + a backlit bloom (dark high-contrast grade) and a minimal floating HUD (SVG diamonds/dotted lines + monospaced ticking readouts). All the visuals are `.gp-*` CSS in [src/index.css](src/index.css); the component only wires layers + readout state, and honors `prefers-reduced-motion`. Note: a true subject-only silhouette needs a background-removed PNG — on the flat JPG it's approximated with the bloom + grade. No name/contact overlay on the front (those live in `HomeIntro` beside it). The back is the **project process** (`process` array: Planning → Considerations → Clear Goal → Implementation → Testing → Deployment) as an elevated numbered step list — deliberately NOT skills (that would duplicate `SkillsSection`). It flips on hover **and** on click/keyboard (so it works on touch and for a11y, not just `:hover`). The 3D mechanics (`perspective`, `preserve-3d`, `backface-visibility`, the `.is-flipped` rotation) are hand-written CSS classes in [src/index.css](src/index.css), not Tailwind utilities, since Tailwind v3 has no core utilities for them.

**LoadingScreen is self-timed.** [src/components/LoadingScreen.tsx](src/components/LoadingScreen.tsx) animates the "MJ…" mark in with `framer-motion`, then calls its `onFinish` prop after ~1.9s (or ~0.4s under `prefers-reduced-motion`); `App` unmounts it via `AnimatePresence`, which plays its `exit` fade before the entrance animation starts.

## Styling conventions

- **Tailwind only** — no CSS modules or styled-components. The `@tailwind` directives appear in both [src/index.css](src/index.css) and [src/styles/globals.css](src/styles/globals.css) (both imported in [src/index.tsx](src/index.tsx)); custom keyframes/global styles (including the flip-card CSS and `html { scroll-behavior: smooth }`) live in [src/index.css](src/index.css).
- **Design language is fixed and should be matched in new UI:** warm, minimal "premium beige" theme, not dark mode. Background is soft beige/cream (`bg-beige-50`, gradients like `from-beige-100 via-beige-50 to-beige-200`); two custom scales are defined once in [tailwind.config.js](tailwind.config.js) and are the single source of truth — **`beige`** (50–900, soft beige → deep mocha) for surfaces/borders/structure, and **`clay`** (50–900, terracotta) as the complementary accent "pop". Don't reach for `amber`/`slate`. Body text uses Tailwind's built-in `stone-*` (charcoal, not pure black/white). Cards are cream (`bg-beige-50`, or `bg-white/60`) with soft shadows (not dark borders/glow) as the primary depth cue, `rounded-2xl`/`rounded-3xl`, `border-beige-200/300` (hover: `border-clay-300/400`). Use `clay` for interactive pops: primary buttons/CTAs (`bg-clay-600 hover:bg-clay-700`), active nav pill, section eyebrow labels (`text-clay-600`), and short divider bars (`bg-clay-500`). Emerald stays for "available/status" badges only.
- **Readability rule (important):** filled clay buttons (`bg-clay-700/800`) use **`text-azure`** (a light sky-blue token in [tailwind.config.js](tailwind.config.js), ~4.7:1 on clay-700) for their labels instead of white — the user specifically asked for azure over white here. Light text in general (`text-azure`, `text-beige-50/100/200`) may ONLY sit on genuinely dark surfaces — the mocha flip-card back (`beige-800/900`), dark carousel covers, and `clay-700`+ buttons. Never put white/cream/azure text on a beige-`100`–`500` background; use `text-stone-*` / `text-clay-700+` on light surfaces. Plain `text-white` on light backgrounds was a repeatedly-flagged bug — avoid it.
- There is no animated background (the old WebGL `AuroraField` aurora was removed as fighting the minimalist direction) — just a static gradient (`App.tsx`) plus a couple of low-opacity blurred blobs (`bg-beige-300/400` + `blur-[120px]`).
- **Custom animations:** `animate-fadeIn` is defined in [tailwind.config.js](tailwind.config.js); `.tech-stack-slide` and the flip-card classes are hand-written in [src/index.css](src/index.css). `framer-motion` variants (stagger/reveal/page-transition/page-entrance) are centralized in [src/components/motion.ts](src/components/motion.ts) — reuse those rather than inlining new ad hoc variants. Add reusable animations to the Tailwind config, one-offs to index.css.

## Static assets

Files in `public/` are served from the site root. The browser-tab favicon is [public/favicon.svg](public/favicon.svg) — the same **"MJ" mark as the header brand** (clay-700 circle, azure text); `index.html` links it as `image/svg+xml` with `favicon.ico` as fallback. `ProfileCard` expects a portrait at `public/portrait.jpg` (falls back to an "MJ" placeholder if missing). Certificate PDFs live in `public/certifications/` and are referenced by absolute path (e.g. `/certifications/GIT-TRAINING.pdf`). In `HomeIntro`, "Download CV" links to `public/resume.pdf` and "LinkedIn" links to the LinkedIn profile — these are two distinct links, not both pointing to the same place.
