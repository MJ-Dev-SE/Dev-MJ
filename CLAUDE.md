# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

This is a Create React App (react-scripts) project. Run from the repo root:

- `npm start` — dev server with hot reload at http://localhost:3000
- `npm run build` — production build to `build/`
- `npm test` — Jest + React Testing Library in watch mode
- `npm test -- --watchAll=false` — run tests once (CI style)
- `npm test -- src/App.test.tsx` — run a single test file
- `npm test -- -t "renders learn react link"` — run tests matching a name

There is no separate lint script; ESLint runs through `react-scripts` (config in `package.json` under `eslintConfig`, extending `react-app`).

## Architecture

Single-page-scroll React 19 + TypeScript portfolio site, styled entirely with Tailwind CSS. No backend — the contact form posts directly to FormSubmit (`https://formsubmit.co/...`), and certificate PDFs are served as static assets.

**Routing & layout shell.** [src/App.tsx](src/App.tsx) is the layout root: it wraps everything in `BrowserRouter`, gates the app behind a branded `LoadingScreen` (shown once per load, then a center-expand entrance animation plays via the `pageEntrance` variant in [src/components/motion.ts](src/components/motion.ts)), and renders a persistent shell — `Navbar` (sticky top header) and `Footer` around a `<main>` holding the `Routes`. There is effectively **one route**, `/` (`Home`, the single scrolling page); `BrowserRouter`/`AnimatePresence`/`pageTransition` are kept for structure and future routes, but everything the user sees lives on `/`. Certifications is a section on that page, not a separate route.

**Pages vs components.** `src/pages/*` are route targets; `src/components/*` are reusable pieces. `Home` is a thin composition root that stacks section components in order: `HomeIntro`, `AboutSection`, `SkillsSection`, `ExperienceSection`, `ProjectsSection`, `MobileSection`, `CertificationsSection`, `ContactSection` — each wrapped in [`<ScrollReveal>`](src/components/ScrollReveal.tsx). Each section is a `<section id="...">` (`home`/`about`/`skills`/`experience`/`projects`/`mobile`/`certifications`/`contact`) with `scroll-mt-24` so the sticky header doesn't cover it when scrolled to. Every section opens with a shared [`<SectionHeading>`](src/components/SectionHeading.tsx) (eyebrow / title / optional lead) — use it rather than hand-rolling heading markup, so type scale and spacing stay identical down the page.

**Scroll reveal is a short fade-up, once.** `ScrollReveal` wraps every section in a framer-motion `whileInView` fade-up (`sectionReveal` + `revealViewport` in [motion.ts](src/components/motion.ts)), firing **once** per section. (It previously used a "reverse spiral" rotate+scale that replayed on every scroll; that was removed as too busy, and its rotation was what pushed content past the viewport edge.) `App.tsx` keeps `overflow-x-clip` (`clip`, not `hidden`, so the sticky navbar still works) as cheap insurance against horizontal scrollbars. Respects `prefers-reduced-motion` (renders children plainly).

**Motion rules of thumb.** Interaction feedback is short and shared: `cardHover` (a 3px lift), `buttonPress` (lift on hover, sink on tap), `staggerContainer`/`staggerItem` for lists, `introContainer`/`introItem` for the hero — all in [motion.ts](src/components/motion.ts). Reuse those rather than inlining ad hoc variants. Two hard-won constraints:
- **Never gate content on an exit animation.** `AnimatePresence mode="wait"` holds the incoming element until the outgoing one finishes animating — and framer-motion animations are rAF-driven, so in a background tab they never finish and the content never appears. This bit both the loading screen (fixed by rendering the page underneath the splash and fading the splash out on top) and the certifications tab panel (fixed by keying the panel on the active tab, no `AnimatePresence`).
- **Prefer CSS transitions for state-driven visuals.** Where a value tracks React state (the ProfileCard step sequence, the rail fill), drive it with conditional Tailwind classes + `transition-*` instead of framer-motion's `animate` prop. It costs nothing per frame and the state stays inspectable in the DOM.

**Navigation is anchor-based, not route-based.** [src/components/Navbar.tsx](src/components/Navbar.tsx) renders plain `href="/#<id>"` links (relying on `html { scroll-behavior: smooth }` in [src/index.css](src/index.css)) and self-manages an `IntersectionObserver` over all eight section ids to highlight the active link (scrollspy). Top-level items are Home / About / Skills / **Experience** / Contact; **Experience is a hover dropdown** whose children are **Projects**, **Mobile** and **Certifications** (those three are not top-level items). The parent highlights when any of experience/projects/mobile/certifications is the active section. There is no sidebar; mobile gets a dropdown panel under the header with the Experience children indented. The active-link indicator uses **dark text on a light `clay-200` pill** (never white text — see the readability rule under Styling).

**Content lives inline in components, not in data files.** Tech-stack groups, experience entries, project cards, and certification lists are hardcoded arrays inside the components that render them:
- `SkillsSection` owns `techStackGroups`, grouped by purpose (Languages / Interfaces / Data & backend / Tooling) and rendered as four cards showing **every** item at once — no tab state to click through.
- `ExperienceSection` owns a resume-style `experience` array rendered as a vertical list, each entry showing its description **and** highlights inline. There is no "see more" modal: the entries are short enough to just read. This is distinct from `ProjectsSection`, which owns the portfolio-piece project entries; they're split by purpose, not duplicated.
- Certifications are two arrays (`fundamentalCertifications`, `aiCertifications`) at the top of [src/components/CertificationsSection.tsx](src/components/CertificationsSection.tsx), tab-switched in the UI. Each card has an explicit **Preview** button (opens a PDF modal — click, Escape, or backdrop to close, with body scroll locked) and an **Open PDF** link; the older hover-to-preview affordance was replaced because hovering to open a full-screen modal is easy to trigger by accident. Each entry points to a PDF in `public/certifications/` (via `filePath`) or an external `link`.

**ProjectsSection is a plain two-column grid.** [src/components/ProjectsSection.tsx](src/components/ProjectsSection.tsx) renders each project as a self-contained card (status pill, timeline, description, highlights, links) with a staggered fade-up on scroll and a small hover lift. **Cards carry no tech chips and the copy never names the stack** — `SkillsSection` already covers what things are built with, so repeating it per card only crowded the text. Mobile apps do not live here: they go in `MobileSection`. It previously arranged the cards on an auto-rotating 3D cylinder driven by a `requestAnimationFrame` loop; that was removed in favor of the grid — the spin made cards unreadable, hijacked pointer events on the side faces, and needed a separate reduced-motion fallback. The old standalone `ProjectCard.tsx` went with it; the card markup now lives in this file.

**MobileSection is the story-carousel one — one snap per app.** [src/components/MobileSection.tsx](src/components/MobileSection.tsx) owns an `apps: MobileApp[]` array (EnergyC today) and shows **one app per phone screen**, Instagram-story style; the left column reads from whichever app is active, so adding an app is one array entry and nothing else. Each entry can carry an `image` (a screenshot in `public/mobile/`, shown full-bleed under a scrim — it falls back to the typographic name card if absent or 404) and a `link` (e.g. the Google Drive build), with `note` shown while there is no link. Every control is hidden when there is only one app.

The track is a horizontal `snap-x snap-mandatory` scroll container, so touch gets **native swipe** while pointer gets left/right tap zones (`hidden md:block` — an always-on overlay would swallow touch drags and scroll the page instead). Three things keep it from stuttering, and they're easy to undo by accident:
- **Read the index only once the scroll settles.** A smooth scroll fires dozens of `scroll` events; acting on each one made the index (and the fill bar) rattle. `handleScroll` debounces ~110ms and commits one update.
- **Pause, don't restart.** `remainingRef` subtracts elapsed time when the timer is torn down, so resuming continues the countdown; the segment fill is keyed on `index` alone and freezes via `animationPlayState`, never remounting mid-slide.
- **Hold to stop.** `pointerdown` pauses and `pointerup`/`pointercancel` resumes, and a release after `HOLD_MS` is swallowed so a hold never also counts as a tap-to-advance.

Autoplay (`SLIDE_MS`, filling the `.snap-fill` keyframe in [src/index.css](src/index.css) — same duration, set inline, so bar and timer agree) runs to the last snap, pauses on hover/focus, is off under `prefers-reduced-motion`, and **switches off for good on the first deliberate move**.

**ProfileCard is a 3D flip card.** [src/components/ProfileCard.tsx](src/components/ProfileCard.tsx) front is [`<Portrait>`](src/components/Portrait.tsx) — `/portrait.jpg` full-bleed, **unfiltered** (falls back to an "MJ" monogram if the file is missing), plus a small "hover or click" hint pill. An earlier version applied a cinematic glitch treatment (slice displacement, chromatic aberration, scan lines, static, HUD readouts) via `.gp-*` CSS; all of it is gone — the photo should read as a photo. No name/contact overlay on the front either (those live in `HomeIntro` beside it).

The back is the **project process** — deliberately NOT skills, which would duplicate `SkillsSection` — drawn as an actual flowchart by [`<ProcessFlowchart>`](src/components/ProcessFlowchart.tsx). It was once a straight six-item numbered list (Plan → Constraints → Definition of done → Build → Test → Deploy); the flowchart re-expresses those same six ideas in flowchart terms, because a straight line isn't how the work goes: **Constraints** and **definition of done** became the two decision diamonds, and **Test** became the No-branch that loops Build back around. Flow is `The brief → Plan → [Scope & constraints agreed?] → Build → [Meets definition of done?] → Ship & watch`, with each `No` looping back.

Flipping the card *traces* the chart: a `setTimeout` chain advances a `revealed` index (`LEAD_IN_MS` + `i * STEP_MS`) through `SEQUENCE` in `ProcessFlowchart.tsx`, which interleaves connectors and nodes so a line always arrives before the node it points at lights up. **Connectors are steps too — keep that alternation if you add nodes.** The step interval (320ms) is deliberately shorter than the `.fc-*` CSS transitions (620–700ms) so elements overlap and it reads as one continuous flow rather than a stutter; total run is ~4s. Unflipping resets it; `prefers-reduced-motion` jumps straight to fully traced. Geometry is hand-placed in a `0 0 300 326` viewBox and scales with `preserveAspectRatio="xMidYMid meet"` — if you move a node, move its connector `d`, arrowhead, and any branch label with it.

The card flips on hover, click/keyboard, **and** focus, so it works on touch and for a11y. The 3D mechanics (`perspective`, `preserve-3d`, `backface-visibility`, the `.is-flipped` rotation) are hand-written CSS classes in [src/index.css](src/index.css), not Tailwind utilities, since Tailwind v3 has no core utilities for them.

**LoadingScreen is self-timed and non-blocking.** [src/components/LoadingScreen.tsx](src/components/LoadingScreen.tsx) shows the "MJ" monogram (the same mark as the navbar brand and favicon), the name, and a thin bar that fills once, then calls `onFinish` after `HOLD_MS` (~1.6s, or 0.3s under `prefers-reduced-motion`). **`App` renders the whole page underneath it** and fades the splash away on top — the page is never gated on the splash's exit animation (see the motion rules above).

## Styling conventions

- **Tailwind only** — no CSS modules or styled-components. The `@tailwind` directives appear in both [src/index.css](src/index.css) and [src/styles/globals.css](src/styles/globals.css) (both imported in [src/index.tsx](src/index.tsx)); custom keyframes/global styles (including the flip-card CSS and `html { scroll-behavior: smooth }`) live in [src/index.css](src/index.css).
- **Design language is fixed and should be matched in new UI:** warm, minimal "premium beige" theme, not dark mode. Background is soft beige/cream (`bg-beige-50`, gradients like `from-beige-100 via-beige-50 to-beige-200`); two custom scales are defined once in [tailwind.config.js](tailwind.config.js) and are the single source of truth — **`beige`** (50–900, soft beige → deep mocha) for surfaces/borders/structure, and **`clay`** (50–900, terracotta) as the complementary accent "pop". Don't reach for `amber`/`slate`. Body text uses Tailwind's built-in `stone-*` (charcoal, not pure black/white). Cards are cream (`bg-beige-50`, or `bg-white/60`) with soft shadows (not dark borders/glow) as the primary depth cue, `rounded-2xl`/`rounded-3xl`, `border-beige-200/300` (hover: `border-clay-300/400`). Use `clay` for interactive pops: primary buttons/CTAs (`bg-clay-700 hover:bg-clay-800`), the active nav pill, section eyebrow labels (`text-clay-600`), list bullets, and the navbar's scroll-progress line (`bg-clay-500`). Emerald stays for "available/status" badges only.
- **Readability rule (important):** filled clay buttons (`bg-clay-700/800`) use **`text-azure`** (a light sky-blue token in [tailwind.config.js](tailwind.config.js), ~4.7:1 on clay-700) for their labels instead of white — the user specifically asked for azure over white here. Light text (`text-azure`, `text-beige-50/100/200`) may ONLY sit on genuinely dark surfaces — `clay-700`+ fills (buttons, the active tab pill, the lit step badges on the ProfileCard back). Never put white/cream/azure text on a beige-`100`–`500` background; use `text-stone-*` / `text-clay-700+` on light surfaces. Plain `text-white` on light backgrounds was a repeatedly-flagged bug — avoid it.
- **Surfaces are light throughout.** Cards — including the ProfileCard back, which used to be dark mocha with layered ambient/glass/particle effects — are cream on cream. There is no animated background (the old WebGL `AuroraField` aurora and the blurred hero blobs are both gone): just the static top-to-bottom gradient in `App.tsx`.
- **Custom animations:** `animate-fadeIn` is defined in [tailwind.config.js](tailwind.config.js); `.hint-bob`, the `.fc-*` flowchart states, and the flip-card classes are hand-written in [src/index.css](src/index.css). The `.fc-*` rules hard-code hex values because SVG `fill`/`stroke` can't take Tailwind text utilities — the palette hexes are listed in a comment there; keep them in sync with [tailwind.config.js](tailwind.config.js). `framer-motion` variants (stagger / section reveal / hover / press / page transition / page entrance) are centralized in [src/components/motion.ts](src/components/motion.ts) — reuse those rather than inlining new ad hoc variants. Add reusable animations to the Tailwind config, one-offs to index.css.

## Static assets

Files in `public/` are served from the site root. The browser-tab favicon is [public/favicon.svg](public/favicon.svg) — the same **"MJ" mark as the header brand** (clay-700 circle, azure text); `index.html` links it as `image/svg+xml` with `favicon.ico` as fallback. `ProfileCard` expects a portrait at `public/portrait.jpg` (falls back to an "MJ" placeholder if missing). Certificate PDFs live in `public/certifications/` and are referenced by absolute path (e.g. `/certifications/GIT-TRAINING.pdf`). In `HomeIntro`, "Download CV" links to `public/resume.pdf` and "LinkedIn" links to the LinkedIn profile — these are two distinct links, not both pointing to the same place.
